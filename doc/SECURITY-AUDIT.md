# B3Chain Phase 11: Security Audit Checklist

This document is the master checklist for the B3Chain self-audit. Each item is
backed by an automated test script and a public detail page on
[b3chain.org/testing](https://b3chain.org/testing.html).

**Status legend:**
- `[x]` PASSED — script exited 0 and all assertions held
- `[!]` FAILED — script reported a problem; see notes
- `[ ]` PENDING — script not yet run
- `[-]` N/A — item documented but not testable in current state

**Scope:** This is a self-audit, not an external audit. It covers the
B3Chain-specific code and the integration of **B3PoW-Scratch v1.1**
(see [`contrib/miner/b3miner-rtl/SPEC.md`](../contrib/miner/b3miner-rtl/SPEC.md))
into Bitcoin Core. It does **not** re-audit the underlying Bitcoin
Core 30.2.0 code.

## How to run the full audit

```bash
cd b3chain
bash contrib/testing/audit/run-all.sh
```

This builds `b3chaind` (if not already built), runs all audit scripts in order,
and prints a summary table. Exit code is 0 only if every audit passes.

Individual audits can be run standalone:

```bash
python3 contrib/testing/audit/audit-supply-cap.py
python3 contrib/testing/audit/audit-b3pow-isolation.py
python3 contrib/testing/audit/audit-b3pow-budget.py
python3 contrib/testing/audit/audit-b3pow-cache.py
python3 contrib/testing/audit/audit-b3pow-headers-cap.py
python3 contrib/testing/audit/audit-network-isolation.py
python3 contrib/testing/audit/audit-address-rejection.py
python3 contrib/testing/audit/audit-simd-blake3.py
bash   contrib/testing/audit/audit-rebranding.sh
python3 contrib/testing/audit/audit-hd-coin-type.py
python3 contrib/testing/audit/audit-51-attack-sim.py
bash   contrib/testing/audit/audit-internal-miner.sh
bash   contrib/testing/audit/audit-stratum-pool.sh
bash   contrib/testing/audit/audit-stratum-v2.sh
```

## Reporting

Audit failures are tracked as GitHub issues with the `audit-failure` label.
Security-relevant findings should be reported privately to
**security@b3chain.org** before public disclosure.

References that were intentionally left alone (and are now whitelisted in
`audit-rebranding.sh`):

- Copyright lines and "The Bitcoin Core developers" attribution.
- Lines that contrast old and new names (e.g. `README.md` rename table).
- External URLs (e.g. flathub paths under `org.bitcoincore`).
- The `src/bitcoin-*.cpp` source filenames (we do not rename source files
  to avoid unnecessary churn against upstream merges).
